# 榜单查询问题处理

适用范围：查询失败、中断或授权异常。必须根据脚本错误输出和已有文件状态处理，禁止通过反复重试解决所有错误。

## 处理流程

| 情况 | 处理方式 |
| --- | --- |
| 缺少 Python 或 curl | 说明缺少的依赖，按用户允许的方式安装；不要自动修改系统配置。 |
| LOGIN_REQUIRED | 运行 scripts/auth.py login，由用户本人在浏览器完成授权；最长等待 10 分钟。 |
| HTTP_401 / UNAUTHORIZED | 核查当前授权是否有效后重新登录；AUTH_TOKEN 环境变量优先于本包保存的授权。不要展示令牌或清空其他应用凭据。 |
| HTTP_403 | 根据返回错误核查权限或额度；重新登录或重试不能解决此类问题，向用户说明账号权限限制。 |
| REQUIRED_ARGUMENT_MISSING / UNKNOWN_ARGUMENT | 按[查询指引](query-guide.md)核对参数名称与取值；先运行 `--catalog` 读取实时 schema，再修正参数后重试。 |
| TOOL_UNAVAILABLE | 账号或服务尚未提供该工具，说明情况，不猜测接口。 |
| NETWORK_ERROR | 查询可能已执行，先检查输出路径是否已有结果；确认网络后由用户决定是否重试，不自动更改代理或关闭证书验证。 |
| OUTPUT_EXISTS | 直接读取已保存的结果文件，不重跑查询。 |
| PREVIOUS_ATTEMPT | 只有 `.attempt` 标记没有结果文件时，结果未确认；向用户说明后由其决定是否重新查询，不自动重试可能已计费的请求。 |
| MCP_RPC_ERROR / MCP_TOOL_ERROR / error_code 非空 | 读取结果文件中的错误信息与 request_id，向服务方反馈；不要更换参数反复试探。 |

## 等待与授权

查询期间没有新输出不等于失败。助手工具停止等待时，先检查后台进程是否仍在运行，禁止同时启动同一查询。浏览器授权与脚本需运行在同一台电脑，以接收本机授权回调。

登录完成后的恢复方式：输出路径已有结果文件时直接读取；只有 `.attempt` 标记时停止核查；两者都没有时可用原参数重新执行。不要自动切换账号，不删除标记后盲目重试。

## 反馈与验收

向服务方反馈时提供错误阶段、HTTP 状态、error_code、request_id 和必要的版本信息即可。禁止发送原始请求头、授权文件和含凭据的日志。auth.py logout 仅处理本包保存的共享授权；退出失败时不能宣称已撤销成功，不要删除其他应用的缓存。

# 使用问题处理

适用范围：搜索失败或中断。必须根据错误和已有任务状态处理，禁止通过重复创建任务尝试解决所有错误。

## 处理流程

| 情况 | 处理方式 |
| --- | --- |
| 缺少 Python 或 curl | 说明缺少的依赖，按用户允许的方式安装；不要自动修改系统配置。 |
| 没有安装 ffprobe | 正常继续上传，无需安装。视频时长与有效性由服务端最终检查。 |
| 本地检测视频超限或无效 | 说明错误，请用户选择符合要求的文件；不要擅自转码。 |
| LOGIN_REQUIRED | 运行 auth.py login，由用户本人在浏览器完成授权。 |
| HTTP 401 | 核查当前授权是否有效；AUTH_TOKEN 环境变量优先于本包保存的授权。不要展示令牌或清空其他应用凭据。 |
| HTTP 403 | 根据返回错误核查权限或额度；重新创建任务不能解决此类问题。 |
| MEDIA_NOT_FOUND | 检查是否为同一账号和原任务，将 request_id 提供给服务方排查。 |
| 上传中断或超时 | 等待脚本核验原任务，不自动重新上传或创建新票据。 |
| PROCESSING_WAIT_LIMIT | 使用原 work_dir 执行 --resume，继续原查询。 |
| EXISTING_ATTEMPT / NO_CONTINUATION_STATE | 保留任务记录，不能删除标记后重试；联系服务方核查。 |
| TASK_LOCKED | 确认原进程是否仍在运行；仅确认已退出后才可删除该任务的 run.lock 并续查。 |
| failed / expired | 报告任务失败或过期，由用户决定是否重新搜索。 |

登录完成后的恢复方式：有 private-task.json 时续查；只有 attempt.json 时停止核查；两者都没有时可使用原参数和原 work_dir 重新执行。不要自动切换账号。

## 等待与续查

上传期间没有新日志不等于失败。助手工具停止等待时，先检查后台进程是否仍在运行，禁止同时启动同一任务。

浏览器授权与脚本需运行在同一台电脑，以接收本机授权回调。上传票据有效期不等于已完成任务的有效期，任务状态以服务返回为准。续查使用保存的原查询，不擅自修改条件。

## 清理和诊断验收

--cleanup 仅清理指定任务的本地续查令牌；auth.py logout 仅处理本包保存的授权。退出失败时不能宣称已撤销成功。不要删除其他应用的缓存。

向服务方反馈时提供错误阶段、HTTP 状态、error_code、request_id 和必要的版本信息即可。禁止发送原始请求头、授权文件、上传票据和含凭据的日志。普通用户无需运行开发测试。
